## 1. 背景与目标

### 1.1 现状缺口

当前 optix 提供单标的分析（technical / options / strategy），但**无组合层视角**：
- 无法回答"我整个账户 net delta 多少"
- 无法回答"SPY 跌 3% 我浮亏多少"
- 无法主动告警"单标的权重 > 15%"

### 1.2 真实场景驱动

用户账户 5/30 快照：
- TSLA 30%（已减仓至 8%）+ GOOGL 21% 历史性双重过度集中
- 14 个 underlying，多个含期权 leg
- Net Liq SGD $452,929 / USD $354,477（FX 1.2765）

集中度问题反复出现但没有任何自动监控——这是 v2.0 的核心动因。

### 1.3 范围

新增三个组合层 CLI 子命令，共享同一份持仓快照：
- `optix portfolio concentration` — 集中度 + 阈值告警（**Phase 1**，纯 Go）
- `optix portfolio greeks` — Δ/Γ/V/Θ 聚合（**Phase 2**，需 Python + proto）
- `optix portfolio stress` — 场景化 P&L 模拟（**Phase 3**，依赖 Phase 2 重定价）

**显式不做**：真实下单（保持 read-only 安全边界）；L2 order book（不做高频）；options flow 订阅型数据（性价比低）。

## 4. Phase 1 · Concentration（Week 1）

### 4.1 实现要点

- **纯 Go**，零 Python / proto 依赖
- 直接消费 `model.Position[]` + `broker.GetAccountSummary().NetLiq{USD,SGD,FX}`
- 期权按 underlying 聚合（用 abs(market_value) 防 short 抵消）
- 阈值：单标 > 10% ⚠️、> 20% 🔴（可通过 `--threshold` 覆盖）

### 4.2 计算指标

| 指标 | 公式 |
|---|---|
| 单标权重 | `abs(mv_usd) / net_liq_usd` |
| Top-N 集中度 | `Σ top-N 权重` |
| HHI (Herfindahl) | `Σ (weight_pct)²` × 10000（< 1500 分散 / > 2500 集中） |
| Sector 集中度 | 按 `configs/sectors.json` 映射后聚合 |
| Deployed 比例 | `Σ abs(mv) / net_liq` |

## 5. Phase 2 · Greeks 聚合（Week 2）

### 5.1 Proto 新增

`proto/optix/analysis/v1/portfolio.proto`：

```protobuf
syntax = "proto3";
package optix.analysis.v1;

import "optix/marketdata/v1/types.proto";

option go_package = "github.com/IS908/optix/gen/go/optix/analysis/v1;analysisv1";

service PortfolioService {
  rpc AggregateGreeks(AggregateGreeksRequest) returns (AggregateGreeksResponse);
  rpc RunStressScenario(StressScenarioRequest) returns (StressScenarioResponse);
}

message PositionLeg {
  string symbol = 1;              // SPY / TSLA_2026-12-18_C420
  string underlying = 2;
  int32 quantity = 3;             // signed: short = negative
  bool is_option = 4;
  optix.marketdata.v1.OptionType option_type = 5;
  double strike = 6;
  string expiration = 7;           // YYYY-MM-DD
  double mark = 8;
  double underlying_price = 9;
  double iv = 10;
  bool iv_unavailable = 11;        // staleness check 失败时为 true
  int64 iv_cache_age_seconds = 12; // 用于客户端二次判断
}

message AggregateGreeksRequest {
  repeated PositionLeg positions = 1;
  double net_liq_usd = 2;
  string group_by = 3;             // "underlying" | "sector"
  double risk_free_rate = 4;
}

message AggregateGreeksResponse {
  message Group {
    string key = 1;
    double mv_usd = 2;
    double weight_pct = 3;
    optix.marketdata.v1.Greeks greeks = 4;
    int32 leg_count = 5;
    int32 skipped_leg_count = 6;
  }
  repeated Group groups = 1;
  optix.marketdata.v1.Greeks total_greeks = 2;
  double total_mv_usd = 3;
}
```

### 5.2 IV 缓存时效性校验（**核心子规范**）

**问题**：Greeks 对 IV 极度敏感。IV 越旧，Greeks 越假，stress test 越不可信。

**SQLite schema 变更**：

```sql
-- 新增列（migration 002_iv_cache_timestamp.sql）
ALTER TABLE analysis_cache ADD COLUMN iv_cache_updated_at TIMESTAMP;
```

**Staleness 四档策略**：

| 档位 | Action | 显示标记 | 阈值（可在 configs/portfolio.yaml 覆盖） |
|---|---|---|---|
| 🟢 Fresh | 直接用 | `✓` + 年龄 | < 4h（同盘段） |
| 🟡 Acceptable | 用，加 warning | `⚠️ stale Xh` | 4h - 24h（跨盘段） |
| 🟠 Stale | 用，强警告 | `⚠️⚠️ stale Xd` | 24h - 7d |
| 🔴 Unusable | 拒绝计算，标 `iv_unavailable=true` | `✗ stale Xd (skipped)` | > 7d 或缺失 |

**Go 侧实现** (`internal/portfolio/staleness.go`)：

```go
type IVFreshness int

const (
    IVFresh IVFreshness = iota
    IVAcceptable
    IVStale
    IVUnusable
)

func ClassifyIV(updatedAt time.Time, cfg StalenessConfig) IVFreshness {
    age := time.Since(updatedAt)
    switch {
    case age < cfg.FreshMax:
        return IVFresh
    case age < cfg.AcceptableMax:
        return IVAcceptable
    case age < cfg.StaleMax:
        return IVStale
    default:
        return IVUnusable
    }
}

// 在 aggregator.go 构造 PositionLeg 时调用
func (a *Aggregator) buildLeg(p model.Position, ivCache *IVCacheEntry) PositionLeg {
    leg := /* ... */
    if ivCache == nil || ClassifyIV(ivCache.UpdatedAt, a.cfg) == IVUnusable {
        leg.IvUnavailable = true
        leg.Iv = 0
    } else {
        leg.Iv = ivCache.Value
        leg.IvCacheAgeSeconds = int64(time.Since(ivCache.UpdatedAt).Seconds())
    }
    return leg
}
```

**Python 侧约定** (`portfolio/greeks.py`)：

- 收到 `iv_unavailable=true` 的 leg：返回该 group 的 `skipped_leg_count` 自增，该 leg Greeks 全置 0，**不计入** group/total 聚合
- 不抛错（保证整个命令仍出结果，仅缺数据时如实标注）

## 6. Phase 3 · Stress Test（Week 3）

### 6.1 内置场景

```yaml
# configs/portfolio.yaml
scenarios:
  - id: spy-down-3
    label: "SPY -3%"
    shocks:
      - axis: spy_pct
        magnitude: -0.03
  - id: spy-down-5
    shocks: [{axis: spy_pct, magnitude: -0.05}]
  - id: spy-down-10
    shocks: [{axis: spy_pct, magnitude: -0.10}]
  - id: vix-up-50
    shocks: [{axis: vix_pct, magnitude: +0.50}]
  - id: qqq-down-5
    shocks: [{axis: qqq_pct, magnitude: -0.05}]
  - id: tech-correlated-5
    shocks:
      - axis: spy_pct
        magnitude: -0.03
      - axis: vix_pct
        magnitude: +0.30
```

### 6.2 Beta 计算

- Source: `datastore/sqlite` 已缓存的 OHLCV bars
- 窗口：60 个交易日
- 公式：`β = cov(ret_symbol, ret_spy) / var(ret_spy)`
- 缓存：30 天有效期，存 SQLite `symbol_beta` 表

### 6.3 重定价管线

对每个 (scenario, leg) 组合：
1. 计算新 underlying_price：
   - 市场级 shock: `new_price = price × (1 + shock × beta)`
   - 单标 shock: `new_price = price × (1 + shock)` if symbol matches
2. 计算新 IV（仅 VIX shock 时）：`new_iv = iv × (1 + vix_shock × 0.6)`（粗略转换系数，可调）
3. 复用 Phase 2 pricer 重定价
4. ΔP&L = (new_price - old_mark) × qty × multiplier

## 7. 已决策的设计选项

| # | 问题 | 决策 | 理由 |
|---|---|---|---|
| 1 | Beta 数据源 | 算自 60d OHLCV (已缓存) | 自洽，不依赖外部数据 |
| 2 | Sector 映射 | 硬编码 `configs/sectors.json` | 静态够用，约 30-50 主流票 |
| 3 | 期权 IV 来源 | Cache from 最近 analyze + 4 档 staleness 校验 | 性能 vs 准确性的平衡 |
| 4 | NLV 货币显示 | USD + SGD 双列 | 用户账户基底是 SGD |
| 5 | JSON 导出 | 终端输出 + `--json` flag 同步导出 | cron 需要消费 |
