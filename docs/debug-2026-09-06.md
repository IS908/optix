## 已修复

1. **直接启动使用错误的 Python 环境。** 默认 `python3` 在本机指向系统解释器，同一条 `pulse --view intraday --format json` 返回 0 个资产；显式指定项目虚拟环境返回 9 个。现在优先使用二进制所属 runtime 的 `python/.venv/bin/python`，其次当前源码目录的虚拟环境，最后回退 `python3`；保留 `--python` 覆盖。新构建的 HTTP `/api/intel/pulse` 已返回 9 个资产。
2. **缺失数据产生错误的“偏多”信号。** P/C 失败时默认零值参与情绪评分，甚至抵消 VIX backwardation 的防御信号。现在按 `PCAvailable` 决定是否计分，所有输入缺失显示“不可用”；有效的零 P/C 仍可参与评分。回归测试覆盖全部缺失、单项缺失及有效零值。
3. **短请求取消污染冲击模块共享缓存。** 自动视图探测的 1.5 秒请求可能超时，其空报价、深度、期权结果此前被缓存 60 秒。现在取消/超时结果不进入 TTL 缓存，并保留被底层 subprocess 错误丢失的 context 错误类型。测试验证后续正常请求能立即恢复。此项修复通过回归测试，尚未完成真实行情下的再次验收。
4. **Python lint 失败。** 修正组合扫描测试的两处中途 import 和两处模糊变量名。
