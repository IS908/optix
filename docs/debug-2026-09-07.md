# 2026-09-07 IB Gateway acceptance

Baseline: `4e61973` plus the shock budget fixes in this change. All live requests
used temporary databases and the project Python virtualenv. No user database,
installed runtime, or trading orders were changed. US equities were closed for
Labor Day ([NYSE calendar](https://www.nyse.com/trade/hours-calendars)).

## Connection and market-data evidence

- Gateway `127.0.0.1:4001` accepted connections. A 1.5s Connect context failed
  before dialing: the IBKR client requires a 2s handshake window plus 1s reserve.
  A 3.5s context connected in 0.026s; an 8s context connected in 0.195s.
- Direct SPY historical request returned 390 five-minute bars in 4.23s.
  The 8s intraday snapshot returned quotes for 8/9 symbols and 78 bars per symbol
  for all nine symbols. These are historical bars, not current-session acceptance.
- SPY chain structure returned 3,864 contracts across four expirations in 1.03s.
  A 6s OI/IV request attempted 416 contracts but returned no positive OI/IV/volume.
  A single SPY 773 put for 2026-09-08 returned a mark with explicit missing
  bid/ask/last/OI/IV/Greeks warnings. This does not establish live option coverage.
- IBKR stock quotes explicitly reported no market data subscription and timed-out
  historical fallback. SMART depth returned IB error 2152 requesting additional
  exchange permissions for SPY/QQQ/TLT/LQD; other requests timed out without rows.
  Missing OPRA data cannot yet be attributed solely to permissions or the holiday.

## Fixes

1. Separate the bounded 4s handshake from the 1.5s quote/depth collection window.
   The parent deadline still limits both, including short automatic view probes.
2. Reserve up to 100ms of the option deadline for aggregating and returning rows.
   Previously a slow symbol could consume the caller's entire deadline and make
   the service/TTL layer discard an already completed fast symbol.
3. Preserve successful depth rows when another symbol returns an error. Keep the
   per-symbol warning instead of throwing away the entire partial result.

## Follow-up: issue #212 option availability

Rechecked all four open issues against released v0.16.0. #212 still had contained
code defects: chain enrichment never assigned volume, an OI-only row exposed
unavailable IV skew/volume as zeros, and spot lookup exhausted each symbol's
remaining deadline before metric subscriptions could start.

The follow-up captures standard per-contract VOLUME/DELAYED_VOLUME ticks (not
side aggregates), filters opposite-side OI, and retains collected ticks across
cancellation or broker errors. The source model cannot distinguish an absent
size from a reported zero, so zero totals are conservatively marked unavailable.
`missing_metrics` is additive to the option-stress JSON; the UI renders dashes
for unavailable metrics while still displaying a measured zero IV skew. Volume
and OI are explicitly observed-contract totals, not proof of complete coverage.
Tick semantics reference: [IBKR tick types](https://interactivebrokers.github.io/tws-api/tick_types.html).

Spot lookup now uses at most one quarter of the remaining deadline, capped at
1s. The existing median-strike fallback remains only a filtering hint, never an
actual underlying quote. A FIFO pool of five workers processes the full eligible
window with ATM calls and puts first. The outer two-chain concurrency and parent
deadlines remain in force. Subscription notices 354/10167 are retained for
diagnostics without stopping delayed ticks. Error/done races retain the cause.

The final bundle exited 0 in 12.81s, but all four symbols still lacked positive

remaining absence cannot be attributed exclusively to OPRA permissions. #212
therefore remains open for subscribed trading-session acceptance. These timings
show collection now receives time; they do not prove sufficient time for complete
coverage or establish a latency benchmark.
